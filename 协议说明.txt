传输协议：HTTP/1.1（基于 Kestrel Web 服务器，HTTP over TCP，明文局域网直连）

一、数据面
- 手机 → 电脑：PUT 分块上传（每块 4MB，JSON 控制接口 + 二进制块传输）
- 电脑 → 手机：GET 下载，浏览器原生下载器，支持 HTTP Range 断点续传
- 控制面：配对验证、文件列表等都是 JSON API（/api/...）

二、鉴权（主客双模式，v1.6 起）
所有 /api/* 请求（除配对外）需携带 X-Auth-Token（会话令牌，12 小时有效，活跃自动续期）。

· 访客模式：6 位数字配对码拼入二维码 URL（?code=xxxxxx），
  手机扫码后点「连接」即提交配对码换取令牌；配对码可随时刷新，刷新即失效。

· 主机模式：8 位静态密钥（去掉易混淆字符）持久化保存在本机设置，
  拼入二维码 URL（?key=xxxxxxxx），手机扫码自动提交密钥换取令牌，
  令牌过期后手机用本地保存的密钥自动重新配对；密钥可手动刷新，刷新即全部失效。

· 共同防护：按 IP 计数，连续输错 5 次锁定 30 秒（锁定期间正确凭据也被拒绝）；
  凭据比较使用固定时间算法（FixedTimeEquals）防时序侧信道。

三、选 HTTP 而不是 FTP 的原因
- 手机浏览器原生支持——FTP 在手机浏览器里已基本不可用（ftp:// 早已被移除），
  HTTP 打开网页即用，免装 App
- FTP 需要额外数据通道端口，NAT/防火墙更麻烦；HTTP 单端口即可
- 局域网内 HTTP 的传输速度与 FTP 无实质差别（瓶颈在 Wi-Fi 链路本身）

四、加密说明
文件内容不加密（明文 HTTP）：局域网点对点 + 凭据鉴权场景下加密收益低，
手机端页面有常驻公共场所安全提醒。若未来要跨公网使用，升级 HTTPS 即可。
